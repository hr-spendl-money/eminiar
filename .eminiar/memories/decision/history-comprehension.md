History comprehension (branch feature/history_explorer, v0.4.0, 2026-10-15): `em_history` and the dashboard History tab are built on `src/history/`: `log.ts` reads `git log --all --full-history --numstat` (full-history is required: default simplification drops merge commits that are TREESAME to a parent, which breaks the DAG lanes), refs, tags, blame and `git log -L`; `classify.ts` turns a message plus file list into a kind (conventional commits first, then keywords, docs/test by file list) with scope, issues, PR number and revert target; `szz.ts` is an SZZ-style fix-origin trace: blame the lines a fix removed (as of the parent, whitespace-insensitive, trivial lines filtered) and attribute them to the commits that wrote them. Trace results are cached per fix sha in the `meta` table (`szz:<sha>`) because a commit's diff never changes, with a blame budget per build (120) so a huge repo traces progressively (`tracePending`). The in-memory model is cached per root and keyed on HEAD plus a fingerprint of all ref tips; commit messages are indexed as documents (source `git`, uri `git:<sha>`) so em_search finds them; a `history_brief` meta row feeds the SessionStart project brief without any git work in the hook. No new tables or StorageAdapter methods were needed. Risk scores (file: fix density, traced origins, quick fixes, reverts, 90-day churn; commit: size, spread, hotspot files, later fixes, reverts, breaking, no tests) are signals with listed reasons, not grades. Dashboard charts use a fixed categorical palette for commit kinds (feat blue, test green, perf amber, refactor violet, fix rose, docs sky, other grey) validated for CVD separation; the lane layout is a pure module (`src/ui/web/history/lanes.ts`) with unit tests.
