eminiar is a local-first Claude Code plugin (npm package `eminiar`, MIT, author Ryan Dick, repo github.com/rydn/eminiar) that keeps raw tool output out of the model's context window. It is a clean-room reimplementation of the ideas in context-mode (sandbox exec + FTS5 index + hook-driven session memory), extended with local embeddings (sqlite-vec + bge-small via @huggingface/transformers), file-backed markdown memories, and a tree-sitter/git knowledge graph with symbol-level navigation.

Who it is for: Claude Code users (and their teams) who want the model to run commands, read big files, fetch docs and search history without pasting kilobytes into the conversation. All tools are named `em_*`; slash commands are `/em-stats`, `/em-doctor`, `/em-index`, `/em-search`, `/em-graph`, `/em-purge`, `/em-onboard`.

Main runtime pieces (three tsup bundles in `dist/`, launched through `bin/` shell shims):
- MCP server (`src/server.ts` → `bin/em-server`): registers the 17 `em_*` tools from `src/tools/*.ts` (execute, batch_execute, execute_file, fetch_and_index, index, search, recall, remember, memory, symbols, graph_query, graph_impact, graph_add, reindex, stats, doctor, purge). Declared inline under `mcpServers` in `.claude-plugin/plugin.json`.
- Hook runner (`src/hook.ts` → `bin/em-hook`): one binary handles every Claude Code hook event listed in `hooks/hooks.json` (SessionStart, UserPromptSubmit, PreToolUse on Bash|Read|Grep|Glob|WebFetch|Agent|Task, PostToolUse, PostToolUseFailure, SubagentStop, PreCompact, Stop, SessionEnd). It injects routing guidance at session start, captures tool output into session memory, and in `enforce` routing mode denies native Bash/Read/Grep calls and redirects to the `em_*` equivalent (only while a live server pid marker exists under `~/.eminiar/projects/<id>/servers/`).
- CLI (`src/cli.ts` → `bin/eminiar`): `install [--team] [--marketplace] [--statusline]`, `upgrade`, `uninstall [--purge-data]`, `doctor [--fix]`, `replace-context-mode`, `search`, `graph`, `index`, `reindex`, `stats`, `recall`, `serve --open` (local dashboard UI in `src/ui/`), `statusline`.

Storage: one SQLite DB per project at `~/.eminiar/projects/<id>/eminiar.db` plus a global DB for lifetime stats and the fetch cache; embedding model under `~/.eminiar/models/`; a pinned stable copy of the plugin under `~/.eminiar/plugin/` with its root recorded in `~/.eminiar/root-path`. All SQL lives behind `src/storage/adapter.ts` (`src/storage/sqlite/` is the only module with SQL) so a Postgres/pgvector or libSQL adapter can be added later.

Config precedence: `~/.eminiar/config.json` (user) < `<project>/eminiar.config.json` (team, committed) < `EMINIAR_*` env vars. Schema in `eminiar.config.schema.json` (generated by `scripts/gen-schema.ts`).
